Defining Activity Workflows

An Activity Workflow functions as a sub-workflow embedded within the standard manufacturing workflow. It contains only activity steps that reference Activity Specs, specifically designed to enable the following advanced processing capabilities:

• Spread Processing: Splitting container (or lot) quantities so they can be processed simultaneously across multiple steps within the same path.
• Parallel Processing: Executing multiple tasks or steps on the same container at the same time across different paths.

Unlike the standard workflow, which processes one step at a time, the Activity Workflow allows multiple paths and steps to run concurrently. Activity Workflow requires 1 first step and 1 last step. It starts when a container enters the Activity Sub-workflow Step in the main workflow and concludes when all required activities are completed, returning the container to the standard workflow. For information on Activity Transaction (Txn), refer to the Opcenter Execution Core Shop Floor Guide.

Similar to the standard workflow, a product definition may reference a default workflow that defines the route and processing required to manufacture the product. An Activity Workflow can include multiple elements:

• Steps
• Paths
• Routes
Note: Move In and Move transactions are not allowed once a container enters an Activity Workflow. Move In will be automatically performed for the first Activity Step during the Activity Start transaction if Use Queue is enabled in the Operation.

Refer to the standard workflow page, Understanding Workflows" for information on standard definition.

Steps

A step defines the processing for that point in the workflow. Each step refers to a set of instructions that may include a combination of the following:

• Tasks to be performed by an employee
• Events that must occur to process the container at that step

A spec is a revisioned object that defines the activities carried out at the step. The spec includes the processing instructions for how work is performed. Refer to "Defining Specs" for information on specs.

A workflow step is a step in a workflow that points to a separate workflow through a spec.

A step can contain zero paths, one path, or multiple paths. When a step contains multiple paths, typically there is one default path to another step and alternate paths to other steps.

 

Paths

The direction from one step to the next is called a path. A workflow can have alternate paths from any given step. When alternate paths are available, you can use path selectors to indicate a particular direction.

• Default - Indicated by a solid line. A container follows the default path unless a path selector statement for an alternate path is true.
• Alternate - Indicated by a dotted line. Alternate paths and routes accommodate the need for processing outside the default route. You can create multiple alternate paths from a step and also nest alternate routes. A container follows an alternate path when the path selector for that path is true.

Path Selector Grid in Activity Workflow

The Path Selectors grid in Activity Workflow page behaves differently from the regular workflow. These differences primarily affect how paths are selected, validated, and how parallel allocations are handled.

In the regular Workflow, you have more flexibility where you can select paths even if their associated expressions evaluate to false during a "Move" operation; the selection will appear, and no error message will be displayed. The path selectors grid is designed to allow users to leave the path field empty during a "Move," and the system will automatically select the appropriate path based on its expression.

Conversely, in the Activity Workflow, path selection is more restrictive. Paths with expressions that evaluate to false will not appear as options in the "Next Activity Step" field on the Activity Transaction page. If you attempt to select an invalid path, an error message will be shown. However, a "Default path" will always be available, bypassing expression rules. For "Auto Parallel" setups, the number of path selector records must precisely match the number of available paths, and all paths must be utilized. If any path becomes invalid due to a false expression evaluation during "Auto Parallel," the operation will fail, and an error message will be displayed. Additionally, the "Auto Parallel Allocation (%)" field is introduced in the Activity Workflow to enable auto parallel configuration, while "Status," "Effective From Date," and "Effective Thru Date" fields are removed.

Auto Parallel Allocation (%)

Automate the percentage allocation of processing quantity to available parallel paths. This field will determine the quantity should go to each path when the 'Auto Parallel' flag is enabled in the Activity Step.

This field accepts values from 1 to 100, and the sum of allocations across all paths must equal 100%.

Allocation Conditions:

• If an allocation value is assigned to one path, values must be assigned to the rest of other paths as well, unless the allocation is 100%.
• If 'Auto Parallel Allocation (%)' is assigned, but a path is not executed due to a condition, the transaction will fail with error message.

Default Behavior (Empty Allocation):

• If the 'Auto Parallel Allocation (%)' field is left empty, the system will default to distributing the quantity equally among all applicable paths. Should the total quantity be an odd number, any remaining quantity will be allocated to the first paths. Extra quantities will be added to the first (or first few paths). For example:

- When allocating a total quantity of 100 across three parallel paths, the distribution will be 34%, 33%, and 33%. The additional quantity resulting from rounding is always assigned to the first activity step.

- If an allocation is defined, for example, at 60%-40% with an odd total quantity, the application will assign any remaining odd quantity to the path with the larger percentage. For instance, if the allocation is set at 60%-40% for a total quantity of 101, the first path will receive 61 units and the second path will receive 40 units. The extra quantity is always added to the path with the bigger percentage.

• Paths that are not executed (e.g., due to an expression) will be ignored when the 'Auto Parallel Allocation (%)' is empty.

During a partial quantity "Activity Next" operation with "Auto Parallel" enabled, the system first verifies the existence of records for the subsequent paths. If existing records are found, the system permits the distribution of an insufficient quantity across these next paths. This means some paths may not receive additional quantity during this transaction. This behavior is based on the assumption that all available subsequent paths have already received at least one unit of quantity from a previous "Activity Next" transaction.
